# ABISS: An Arduino-Based Intrinsic Stimulation System for Low-Cost Auditory and Visual Intrinsic Signal Imaging

**Zhili Qu, Kimia Kazemi, Tianyang Wu, Shambulingayya N. Doddapujar, Tyler A. Marrazzo, Matia Gazzola, Howard J. Gritton**

University of Illinois Urbana-Champaign — Departments of Bioengineering, Electrical Engineering, Comparative Biosciences, and Mechanical Science and Engineering

---

## Overview

ABISS is a compact, low-cost, programmable hardware platform for intrinsic optical signal imaging (IOSI) experiments. By integrating sensory stimulus generation, trial timing, and image-acquisition triggering onto a single Arduino-controlled printed circuit board, ABISS reduces cost and system complexity while preserving the flexibility needed for auditory and visual cortical mapping.

The system is designed to address a practical barrier in intrinsic imaging workflows: many existing setups depend on commercial systems (TDT, National Instruments), dedicated acquisition computers, or laboratory-specific MATLAB/LabVIEW/Synapse software to generate stimuli and coordinate trial timing. ABISS replaces this layer with a programmable microcontroller that can be reconfigured simply by editing and uploading new Arduino firmware.

We validate ABISS at both the hardware and biological levels. Auditory stimuli generated by ABISS produced frequency-dependent intrinsic response maps in the auditory cortex that were spatially comparable to maps generated by a commercial TDT RZ6 system (SSIM analysis; median ΔSSIM: −0.012 at 3 kHz, −0.036 at 10 kHz, 0.017 at 30 kHz; all 95% bootstrap intervals include zero). Visual stimulation via the VGA output produced horizontal and vertical retinotopic maps and a visual field sign map with alternating mirror and nonmirror representations consistent with the expected organization of mouse visual cortex, enabling delineation of V1, LM, AL, RL, AM, and PM.

The current prototype is approximately 4 × 3 inches, weighs approximately 150 g, and can be assembled from commonly available components for roughly $150 in parts (excluding camera, illumination, monitor, and speaker).

## Hardware

ABISS is centered on an **Arduino Nano** and interfaces with external devices via three BNC-style coaxial connectors: one digital input (push-button trigger), one digital output (camera trigger), and one general-purpose I/O reserved for future use.

**Audio channel:** An AD9833-based DDS module (GY-9833) generates sine-wave tones via SPI. A PT2258 digital volume controller over I²C provides per-tone amplitude control and smooth fade-in/out ramps. The signal is amplified by an LT1970 stage and delivered via coaxial output to an external speaker.

**Video channel:** A minimalist VGA interface is driven directly by the Arduino. Due to microcontroller clock and memory constraints, the display is subdivided into 8 × 16 pixel blocks, allowing efficient generation of high-contrast drifting-bar patterns (440 × 480 px) refreshed line-by-line via a timer interrupt service routine (ISR).

**Power:** Regulated +5 V DC, stabilized with bulk decoupling capacitors. Voltage conditioning for the analog front end is provided by a MAX660 charge pump.

## Firmware Overview

The firmware was developed in the Arduino IDE using an interrupt-driven architecture to synchronize audio and video outputs while maintaining real-time responsiveness. The two modules run on separate Arduino Nano boards and are synchronized via the shared 20 Hz camera trigger signal.

### Visual Stimulus Firmware

The video subsystem, driven by hardware timers (Timer1: VSYNC, Timer2: HSYNC), generates VGA-compatible signals at 440 × 480 px, 60 Hz by bit-banging RGB and sync pulses through GPIO pins. ISRs ensure precise horizontal/vertical timing. The main loop runs in `SLEEP_MODE_IDLE` between scanlines to minimize CPU usage.

Each visual stimulus consists of a batch of drifting bars with a checkerboard pattern presented on a black background. Bars are rendered as vertical bars sweeping horizontally or horizontal bars sweeping vertically. Bar positions are updated once per logic tick at 20 Hz (every 3rd VGA frame), producing smooth constant-velocity motion. Stimulus motion is organized into directional sweep pairs (e.g., left-to-right followed by right-to-left), separated by a configurable inter-sweep pause during which the screen is blanked and camera triggering is disabled.

**Configurable parameters:**

| Parameter | Default | Description |
|---|---|---|
| `setBarSpeed` | `0.15625` bytes/tick | Bar movement speed |
| `barsPerBatch` | `10` | Bars per sweep |
| `hThicknessBytes` | `5` (40 px) | Horizontal bar width |
| `vThicknessRows` | `3` (48 px) | Vertical bar height |
| `hSpacingBytes` | `61` | Spacing between vertical bars |
| `vSpacingRows` | `34` | Spacing between horizontal bars |
| `numPairs` | `10` | Forward/reverse sweep pairs (0 = loop forever) |
| `sweepsPerPhase` | `1` | Sweeps per direction before reversing |
| `colorFlicker` | `true` | 6 Hz checkerboard polarity flicker |
| `interPairPauseFrames` | ~200 logic ticks (~10 s) | Blank-screen pause between pairs |
| `interPhasePauseFrames` | ~200 logic ticks (~10 s) | Pause between forward and reverse sweeps |
| `direction` | `LEFT_TO_RIGHT` | Starting sweep direction |

### Audio Stimulus Firmware

The audio firmware uses Protothreads to manage concurrent tasks: polling the push-button interface, controlling volume attenuation over I²C (PT2258), and triggering tone trains with configurable fade-in/out ramps. The 20 Hz camera trigger pulse is generated by the `blinkLED` protothread, which controls the camera output pin. The `generateTone` protothread coordinates DDS output and volume ramping relative to each cycle's start time.

Each trial follows this sequence: camera trigger fires at 20 Hz → tone onset after `delayUntilStimulus` → volume ramps up over `numberOfRampUpSteps` → tone holds at target volume for `stimulusTime` → volume ramps down → inter-trial rest. Frequencies cycle through `frequencyList` across trials; the system stops automatically after 30 cycles.

**Configurable parameters:**

| Parameter | Default | Description |
|---|---|---|
| `frequencyList` | `{3000, 10000, 30000}` Hz | Tone frequencies |
| `volumeList` | `{20, 12, 10}` | Target attenuation per frequency (PT2258 scale: 0 = loudest, 79 = muted) |
| `delayUntilStimulus` | `2.0 s` | Delay from camera start to tone onset |
| `stimulusTime` | `2.0 s` | Duration of full-volume tone |
| `delayAfterStimulus` | `2.0 s` | Post-tone delay before cycle end |
| `restTimeInSeconds` | `30.0 s` | Inter-trial rest period |
| `blinksPerSecond` | `20.0` | Camera trigger rate |
| `numberOfRampUpSteps` | `150` | Volume fade-in resolution |
| `numberOfRampDownSteps` | `150` | Volume fade-out resolution |
| `stepIntervalInSeconds` | `0.0005 s` | Time between ramp steps |
| `buttonToStartTime` | `1.0 s` | Delay from button press to stimulus onset |

## Experimental Protocol

### Auditory Intrinsic Imaging

Each trial: 1.5 s baseline → 1 s pure tone at 75 dB SPL (3, 10, or 30 kHz) → 28.5 s inter-trial gap. Images acquired at 20 Hz under 625 nm red light illumination. Response maps computed as ΔR/R (frames 41–80 vs. baseline frames 1–30), spatially smoothed (Gaussian σ = 3), and averaged across trials.

### Visual Intrinsic Imaging

Drifting-bar stimuli in four cardinal directions (top-to-bottom, bottom-to-top, left-to-right, right-to-left), n ≥ 9 trials per direction. Retinotopic maps generated using phase-encoded Fourier analysis with opposite-direction phase subtraction to cancel hemodynamic delay. Visual field sign maps computed from local gradients of horizontal and vertical retinotopic maps.

### Signal Timing

```
Visual:  [ forward sweep ] [ ~10s pause ] [ reverse sweep ] [ ~10s pause ] ... × numPairs
Audio:   [ delay ] [ ramp up ] [ tone ] [ ramp down ] [ rest ] ... × 30 cycles
Camera:  _____|‾‾‾‾‾‾‾‾‾‾‾|____________  (20 Hz, active during motion/stimulus only)
```

## Operation

### Visual Stimulus
1. Upload `visual_stimulus.ino` to an Arduino Nano and connect to a VGA monitor using the wiring table above.
2. Press the button on D9. The system begins sweeping checkerboard bars across the screen.
3. After each forward + reverse pair, the screen blanks for the inter-pair pause, then continues automatically.
4. After `numPairs` pairs, the screen clears and the system returns to idle. The D8 pin outputs the 20 Hz camera trigger during active bar motion only.

### Audio Stimulus
1. Upload `audio_stimulus.ino` to a separate Arduino Nano with AD9833 and PT2258 connected.
2. Press the button on D9. After `buttonToStartTime` delay, the stimulus sequence begins.
3. The system runs 30 frequency cycles automatically, then stops. Press the button again to restart.

## Limitations

Because ABISS is based on an Arduino Nano, it is constrained by microcontroller clock speed, memory, and storage capacity. The VGA output is sufficient for simple high-contrast patterns such as sweeping bars and grids, but is not suited for complex naturalistic scenes, high-resolution textures, or dynamically corrected curved-screen stimuli. The current design supports a single speaker configuration, limiting suitability for binaural or multi-speaker spatial stimulation. Experiments requiring multi-channel auditory output, high-resolution visual rendering, closed-loop behavioral control, or large-scale synchronized acquisition may be better served by commercial systems or GPU-based stimulus platforms.
